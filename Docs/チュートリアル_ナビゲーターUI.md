# チュートリアルのナビゲーターUI

## 表示と操作

- 会話中：盤面を暗くする全画面オーバーレイ。右にナビゲーターの上半身、左に吹き出し。画面タップで次へ進む。
- 操作中：会話を閉じ、左側に具体的な操作ガイドを残す。配置位置、方向選択、ターン終了、敵行動で内容を切り替える。
- 敵行動の「HPに注目！」中は、実際のHP表示の周囲12pxを残し、それ以外に32%の黒を重ねる。4枚の非操作パネルで穴を作り、画面サイズやHP表示の位置に追従する。敵行動後も0.8秒残して減少後の数値を見せ、次の会話・別の指示・終了・スキップ・敗北では解除する。
- ナビゲーターの表情：通常、説明、驚き、成功、考える、の5種類。
- 配置練習は既存の4手（A↑、D↑、F↑、A→）と既存のTargetMarkerを維持する。マップ、駒の性能、初期HP・コストは変更しない。
- 会話中や配置練習中はターン終了を無効にする。配置完了後のターン終了ガイドで有効にする。本編のターン終了条件は従来どおり。
- 会話を進めたフレームとその次のフレームは、配置・方向確定・ターン終了に同じ入力を使わない。
- 配置後は1.1秒待って演出を見せる。最終手の後はGameClearを確認して完了会話へ進む。
- 右上のスキップは会話オーバーレイの子として配置し、ナビゲーターの会話中だけ表示する。操作ガイド・方向指定・敵行動・HPへの注目中は非表示。通常終了・スキップでは状態と表示を解除してステージ選択へ移動。万一の敗北時は会話を隠して既存のリトライ画面を使う。

## 素材

原本：`Assets/Material/navi.psd`。変更せず、`Tools/export_navigator.py`で共通パーツと顔線画を合成する。顔差分は元レイヤーの0始まりインデックスで4、5、7、10、11。眉は原本で表示中のものを共通利用する。

書き出し先：`Assets/Art/TutorialNavigator/`。全5表情を同じ範囲で切り出し、同じ縦1024pxの透過PNGにする。UnityにはUI用のSingle Spriteとして取り込む。吹き出しの尾も同フォルダに置く。

会話の吹き出しと左側の指示パネルは、専用の`white_panel.png`を使用する。中心が不透明な白の角丸画像を9-slice（上下左右24px）で拡大し、Imageの色を白・alpha=1、Fill Centerを有効にする。Unity組み込みSpriteへの参照には依存しない。

ナビゲーターUIのスキップボタンも同じ背景Spriteを使用する。検証メニューでは、MainSceneの非表示オブジェクトを含む全Imageについて、Unityが解決したSpriteの型・Texture・borderを確認する。MissingReferenceExceptionが発生する場合は、問題のImageのオブジェクト名を付けて報告する。

再書き出し：Pillowが利用できるPythonで `python Tools/export_navigator.py`。PSD構成が変わった場合は自動書き出しを停止し、差分の割り当てを見直す。既存のmetaファイルは維持する。

## 編集箇所

- 台詞・操作指示・表情の割り当て：`Assets/Scripts/TutorialManager.cs`
- 表示とタップの受付：`Assets/Scripts/TutorialDialog.cs`
- 見た目とSprite参照：`MainScene`のルートにある`TutorialPresentation`
- 吹き出し：`ConversationOverlay/NavigatorSpeechBubble`
- 立ち絵：`ConversationOverlay/NavigatorPortrait`
- 操作ガイド：`TutorialInstruction`

チュートリアルCanvasは1600×900基準、Screen Space Overlay、sortingOrder=200。通常UIのCanvasGroupから独立させ、方向指定中の通常UI無効化に巻き込まれないようにする。フェードのCanvas（999）より下に表示する。

ゲーム内メニューのボタンとパネルは独立した`PauseMenuCanvas`（Screen Space Overlay、sortingOrder=300）に配置する。指示文・HPへの注目（200）より手前に表示する。会話オーバーレイには独立したCanvas（Override Sorting有効、400）とGraphicRaycasterを設定し、会話中はメニューを背面に置いてタップを遮断する。フェード（999）はさらに手前に表示する。

## 検証

### 新しい駒のミニ解説

`StageUnitIntroduction`の`introductions`配列で、本編の初登場マップと駒データ・ナビゲーター口調の助言を設定する。既存の右側ナビゲーター＋左側吹き出しを使い、実際の駒の画像と`GetDescription()`による性能、ワンポイントを表示する。名前欄は空欄で、カードの内容は上に寄せて配置する。

| マップ | 紹介する駒 |
| --- | --- |
| map7 | B：配置時に上下左右を攻撃 |
| map8 | K：配置時に一列を攻撃 |
| map9 | F：HP回復 |
| map10 | O：配置時に指定方向を攻撃 |
| map16 | G：指定方向の敵の攻撃力を下げる |
| map17 | H：上下左右の敵の攻撃力を下げる |
| map19 | D：ターン終了時に指定方向を攻撃 |
| map20 | E：ターン終了時に上下左右を攻撃 |

初期のA・Cは対象外。D・Fは本編での初登場に合わせて紹介する。使用可能な駒が増えないマップや、現在どのマップにも登場しない駒には追加しない。

閉じるタップを受け付けた時点で、プロフィールの`seenUnitIntroductions`に対応する駒IDを保存する。既存のBの既読記録もそのまま引き継ぐ。以後の対象マップ再ロード・リトライ・次回起動では表示しない。説明の途中で終了した場合は既読にせず、次回再表示する。既存プロフィールでは未追加のリストを空で補完し、ステージ番号やクリア履歴の移行は変更しない。タイトルのキャッシュクリアで既読も初期化できる。

ミニ解説中も通常の会話と同じくメニューは操作できず、配置・方向指定・ターン終了・駒選択を止める。閉じたタップと次フレームはゲーム操作に使わない。4手のチュートリアルとそのスキップ表示条件は変更しない。

ゲームコード・Editor検証コードのコンパイル、および実際の紹介処理・会話UI・プロフィール・駒データを使った代替エンジン／保存先での単体検証が成功。初回表示、画像と性能と助言、既読保存、再ロード抑制、旧セーブの補完、キャッシュクリア、他マップとチュートリアルの対象外判定、途中終了時の未読維持、通常会話レイアウトへの復帰と入力遮断を確認した。シーンの参照・親子関係・元の配置の保持・フォント収録文字も静的に確認。Unity実画面での描画・クリックは未確認。

### タイトルからのデバッグ用初期化

タイトル左上のメニューに「キャッシュクリア」を追加。チュートリアル完了状態・ステージのクリア記録（現行プロフィールと旧形式のキー）を既存の`GameSession.ResetAllProgress()`で初期化する。音量設定は保持する。初期化後にメニューを閉じてゲームを開始すると、チュートリアルから始まる。ボタンの下に削除対象と実行結果を表示する。本編のメニューには追加しない。

ボタン経由の初期化、メモリ上と保存用プロフィールの更新、旧キーの削除、音量と無関係な設定の保持、繰り返し実行、次のゲーム開始がチュートリアルへ進むことを、実際のコードと保存先をメモリに置き換えた単体環境で検証済み。ユーザーの保存データはこの検証では変更していない。実際のUnity画面でのクリックは未確認。

### ナビゲーターUI

- Unity同梱RoslynによるゲームコードとEditor検証コードのコンパイル成功。
- シーンのローカル参照、ID重複、コンポーネントの所属、親子関係、5表情の画像と参照を静的検証。
- 実際のTutorialManager/Dialogのコルーチンをエンジン代替環境で実行し、4配置・3敵ターン、誤配置拒否、方向選択とキャンセル、完了、スキップ、途中退出・再試行、本編での非表示、タップ遮断を検証。Unityの物理・描画・バトルの検証ではない。
- Unityバッチ起動はライセンスクライアントへの接続失敗（exit 199）で停止。Editor上の検証メニュー、実際の描画・タッチ・通しプレイは未確認。

Editor起動後は `Tools > IGOtower > Validate Tutorial Presentation` で参照を確認できる。Playモードではタイトルからチュートリアルを開始し、会話→4配置→完了会話→ステージ選択、会話中のスキップ、操作・敵行動・HP注目中はスキップが非表示になること、途中退出・リトライ、対象外マップではナビUIが表示されず、上記8マップの未読の紹介だけが表示されることを確認する。960×540で吹き出し・ガイドの読みやすさと盤面への重なりも確認する。


### map12の配置制限の説明

map12初回ロード時は、駒紹介と同じナビゲーター／吹き出しの通常会話で、上下左右を敵に囲まれたマスには味方を配置できず、隣接する敵をどれか1体倒すと配置できることを説明する。中央の空きマス（盤面座標2,2）が対象の形になっている。`RuleSystem.CanPlaceAlly`は盤外・穴も塞がれた方向に数えるが、このマスの4方向はすべて敵である。

設定は`StageUnitIntroduction.stageTutorials`の`surrounded-placement`。閉じた時点で`GameProfile.seenStageTutorials`に既読を保存し、リトライ・次回起動では再表示しない。途中終了なら未読のまま。旧セーブでは未追加のリストを空で補完し、駒紹介の既読とクリア履歴は保持する。タイトルのキャッシュクリアでこの既読も消える。会話中の盤面／メニューへの入力遮断と、閉じるタップの盤面への伝播防止は既存の`TutorialDialog`を共有する。

ゲームコードとEditor検証コードのコンパイル、代替エンジン／保存先を使った実コードの初回表示・対象外マップ・途中退出・既読保存・リトライ抑制・キャッシュクリアを確認。Unity実画面での表示・操作は未確認。
